# Шаблон Ганта: `drawing` с объектом `GanttChart`

Дата: 22.10.2026. Последний файл, мешающий полному паритету:
`Reports/Gant1C/Templates/пмГант_Гант/Ext/Template.xml` (1960 из 1961
совпадают).

## Что расходится

В нативном шаблоне есть элемент `<drawing>` с вложенным объектом
`d3p1:GanttChart`; в нашей выгрузке его нет вовсе. Плюс связанные с ним
`formatIndex` и границы ячеек — всего 369 строк различий.

## Структура `<drawing>`

Дочерние элементы в порядке платформы:

```
drawingType          GanttChart
id                   1
formatIndex          61
text                 <v8:item><v8:lang>ru</v8:lang><v8:content>Начало</v8:content></v8:item>
beginRow / beginRowOffset
endRow / endRowOffset
beginColumn / beginColumnOffset
endColumn / endColumnOffset
autoSize             false
pictureSize          Stretch
zOrder               1
object               xsi:type="d3p1:GanttChart"
```

Объект `d3p1:GanttChart` несёт `<d3p1:chart>` с десятками настроек:
`seriesCurId`, `pointsCurId`, `isSeriesDesign`, `realSeriesCount`,
`realExSeriesData` (цвет, линия, маркер), `isPointsDesign`,
`realPointCount`, `curSeries`, `curPoint`, `chartType`, `circleLabelType`,
`labelsDelimiter`, `labelsLocation`, `lbFormat`, `lbpFormat`, `labelsColor`,
`labelsFont` (`AutoFont`), `transparentLabelsBkg`, `labelsBkgColor`,
`labelsBorder` и далее.

## Где это хранится

Проверено на самой записи шаблона (`Config`, строка
`4efcc508-928f-432a-83eb-851a38ef7e7e.0`, распакованный raw-deflate, 53 146
символов):

- подстрок `Gantt`, `drawing`, `seriesCurId`, `d3p1`, `chart` в записи **нет**;
- все 50 блоков `{#base64:…}` — это записи форматов ячеек по ~0.5 КБ
  (`2,1,<uuid>,{9,{"Pattern",…}}`), ни один не содержит настроек диаграммы;
- значит настройки `GanttChart` лежат в **двоичной секции** записи, которую
  `moxel` пока не разбирает, а не в тексте и не в base64-блоках.

`moxel.rs` (писатель шаблонов) вообще не упоминает `drawing`; запись MXL
разбирается на форматы и палитру, а чертёж отбрасывается молча — это и есть
последняя «тихая потеря» в паритете.

### Найденная запись чертежа

По координатам из XML (`endColumnOffset 1029`, колонка 27, строка 12) запись
найдена; она идёт после таблицы форматов:

```
{16,61,{1,1,{"ru","Начало"}},0},   // формат 61 + текст
10,27,0,0,0,27,12,1029,0,1,        // координаты: 27…27, 0…12, смещения 0/1029
e5fdc112-5c84-4a16-9728-72b85692b6e2,  // идентификатор объекта
{
  {19,                             // код типа чертежа (GanttChart)
    {0,
      {11},
      {75,1,0,1,0, …}              // настройки диаграммы
    }
  }
}
```

Рядом лежит `{28,0,nil,13,0,52,1,53,2,…}` — список форматов, на которые
ссылается чертёж (в XML это `formatIndex` и связанные форматы).

Код `19` — единственный кандидат на `drawingType GanttChart`: это
единственный чертёж в записи, он стоит ровно там, где в XML находится
`<drawing>`, а его полезная нагрузка — настройки диаграммы.

## Что уже есть и может пригодиться

- Для форм уже есть сериализатор настроек диаграммы Ганта
  (`mssql_dump/form_body.rs`, namespace `d3p1`), его таблицы свойств можно
  переиспользовать, если удастся прочитать ту же модель из записи шаблона.
- `parse_moxel_*` уже умеет форматы и палитру; `drawing` — отдельная ветка.

## Как искать дальше

1. Сравнить разобранную модель записи с нативным XML: всё, что пишется, уже
   совпадает; значит недостающая секция — это хвост/неизвестный блок записи.
   Найти его можно, сопоставив размер и структуру с шаблоном **без** чертежа.
2. Либо декомпилировать писатель MXL (`mngdsgn`/`moxel`) и найти чтение
   чертежа: там будет и код типа `GanttChart`, и раскладка настроек.
3. После этого — писатель `<drawing>` в порядке из раздела выше и побайтовая
   проверка.

## План

1. Дампом полей записи шаблона найти слот, где лежит `GanttChart`, и снять его
   структуру (как делали для `PlannerField`).
2. Сопоставить настройки с уже известным сериализатором форм; недостающие
   снять с платформы.
3. Написать `<drawing>` (порядок элементов выше) и проверить побайтово.
4. После совпадения — 1961 из 1961.

## Почему это отдельная задача

Это не свойство и не цвет, а целый объект диаграммы с собственной моделью.
Остальные 1960 файлов уже совпадают побайтово.
